# 文档驱动开发

在对代码做任何修改或新增功能之前，严格按以下顺序执行。**不得跳步**。

## 文档与代码的对应关系

| 代码位置 | 对应文档 |
|---------|---------|
| `cmd/swag3/` | `docs/cli.md` |
| `config/` | `docs/config.md` |
| `internal/parser/` | `docs/parser.md` |
| `internal/extractor/` | `docs/extractor.md` |
| `internal/builder/` | `docs/builder.md` |
| `internal/output/` | `docs/output.md` |
| `pkg/swaggin/` | `docs/swaggin.md` |
| 整体架构 / 跨包改动 | `docs/architecture.md` |

## 执行步骤

### Step 1：查阅文档

读取与本次改动相关的 `docs/` 文档，理解：
- 该包当前的职责边界和导出接口
- 改动是否与现有设计一致，或需要调整设计

### Step 2：更新文档

**先改文档，再改代码**。按实际改动更新对应 `docs/*.md`：

- 新增类型 / 函数 → 在文档中补充说明
- 修改现有接口 → 更新文档中的签名和说明
- 删除功能 → 从文档中移除对应条目
- 跨包改动 → 同时更新 `docs/architecture.md`（如数据流、依赖关系有变化）

文档要求：
- 与代码同步，不允许文档描述与实现不符
- 保持简洁，只记录对外可见的契约（导出类型、函数、行为），不记录实现细节

### Step 3：修改代码

按更新后的文档实现功能。代码与文档在同一次改动中对齐。

### Step 4：验证对等

改动完成后，检查：
- 文档中的类型签名、字段名、函数名与代码一致
- 文档中描述的行为与实现一致
- 若发现不一致，立即修正文档或代码

## 特殊情况

- **纯内部实现调整**（不改变导出接口和对外行为）：可不更新文档，但需在 PR / commit 注释中说明"仅内部实现，接口不变"
- **紧急修复**：允许先修代码，但必须在同一个 commit 或下一个 commit 补齐文档更新
