# 代码架构设计

根据用户提供的需求，帮助设计清晰、合理的代码架构。整个流程分为两个阶段：**先出设计稿，确认后再生成实施计划**。

## 执行步骤

### 阶段一：生成架构设计（写入 design.md）

分析用户需求，明确以下信息：
- 项目类型（Web 应用、CLI 工具、库、微服务等）
- 核心功能模块
- 技术栈与语言
- 规模与复杂度

将完整的架构设计写入当前目录下的 `design.md` 文件，内容包括：

**1. 目录结构**
用树形图展示推荐的目录/文件结构，并说明每个目录的职责。

**2. 模块划分**
列出核心模块及其职责，说明模块间的依赖关系。

**3. 数据流**
描述数据在各模块间的流转路径（输入 → 处理 → 输出）。

**4. 关键设计决策**
解释架构选择的理由，包括：
- 分层策略（如 MVC、Clean Architecture、DDD 等）
- 模块边界设定原则
- 扩展性与维护性考量

**5. 待确认事项（可选）**
列出设计中存在的不确定点或需要用户决策的选项。

写入完成后，告知用户：
> `design.md` 已生成，请确认架构设计。确认后回复"确认"或"ok"，我将生成实施计划（plan）。

---

### 阶段二：生成实施计划（用户确认后执行）

用户确认 `design.md` 中的设计后，基于设计内容生成分步实施计划，写入 `plan.md`，内容包括：

**1. 实施阶段划分**
将开发任务拆分为若干阶段，每阶段有明确目标。

**2. 任务清单**
每个阶段列出具体任务，格式：
- [ ] 任务描述（涉及文件/模块）

**3. 优先级与依赖关系**
标明哪些任务必须先完成，哪些可并行。

**4. 关键实现要点**
对复杂模块给出实现提示或代码骨架。

写入完成后告知用户：
> `plan.md` 已生成，可以开始按计划实施。

---

## 设计原则

- **单一职责**：每个模块只做一件事
- **高内聚低耦合**：相关逻辑聚合，模块间依赖最小化
- **依赖倒置**：依赖抽象而非具体实现
- **渐进式设计**：从简单开始，保留扩展空间，避免过度设计
